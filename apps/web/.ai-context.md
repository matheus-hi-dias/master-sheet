# 🧠 AI Context: Master-Sheet (Frontend Web)

Este arquivo serve como a "Fonte da Verdade" para o desenvolvimento assistido por IA dentro do projeto Web do Master-Sheet. Toda geração de código, refatoração de interface ou consumo de API deve respeitar as definições abaixo.

## 🎯 Visão Geral do Projeto

Este projeto é a interface web (Dashboard e Editor de Fichas) do **Master-Sheet**, um ecossistema para gerenciamento de fichas de RPG. Este front-end é focado na experiência de criação das estruturas (Templates, mapeados em JSON) e no preenchimento dinâmico das Fichas (Sheets).

## 🏗️ Tech Stack

- **Framework:** React com Vite (SPA).
- **Estilização:** Tailwind CSS (Utility-first) + Lucide Icons para iconografia.
- **Gerenciamento de Estado/Cache:** React Query (para gerenciar requisições e cache da API).
- **Roteamento:** React Router DOM (v6+).
- **Formulários & Validação:** React Hook Form + Zod (para validação de formulários estruturados da ficha).

## 🛠️ Padrões de Desenvolvimento (Guia de Estilo)

### 1. Componentização e Estrutura

- **Clean Components:** Preferir componentes funcionais puros e dividir lógicas complexas em hooks customizados (`hooks/`).
- **Arquitetura de Pastas:**
  - `src/components/ui/` -> Componentes base genéricos (Botões, Inputs, Modais - ex: Shadcn / customizados).
  - `src/features/` -> Módulos e componentes específicos de regras de negócio (ex: `features/sheets`, `features/templates`).
  - `src/services/` ou `src/api/` -> Comunicação com a API do backend NestJS.

### 2. Estilização e Design System

- O design deve focar em ser **dinâmico, responsivo e imersivo** (Aesthetics). Utilize cores ricas, glassmorphism e animações fluidas se aplicável.
- Usar Tailwind de forma modular. Evitar classes engessadas e preferir ferramentas como `clsx` e `tailwind-merge` (`cn`) para junção de classes dinâmicas.

## 📊 Regras de Negócio Front-End

1. **Manipulação de JSON (Templates vs Sheets):**
   - O coração do front-end é renderizar formulários com base na definição JSON vinda do `Template`.
   - Os dados inseridos pelo usuário devem ser empacotados como JSON e enviados para o campo `data` da `Sheet`.
2. **Dualidade de Tags na UI:**
   - Ao listar/pesquisar Templates globais: As tags são read-only para consumo.
   - Dentro de uma Ficha (Sheet) de usuário: A UI deve permitir que o dono adicione/remova tags livremente, garantindo que isso interaja apenas com a sua ficha.
3. **Validação Dinâmica:**
   - Evitar "confiar" inteiramente no backend. O JSON gerado pela ficha deve ter paridade estrutural com os requisitos estipulados via Template antes da submissão.

## 🤖 Instruções para o Agente (Antigravity)

- **Contexto da API:** Assuma que o Backend (NestJS) se comunica via REST e utiliza UUIDs v4 para entidades.
- **Boas Práticas React:** Evite re-renderizações desnecessárias em formulários complexos gerados a partir do JSON do Template.
- **Commits:** Siga o padrão de Conventional Commits (ex: `feat(ui): add dynamic field validation on sheet editor`).
