# 🧠 AI Context: Master-Sheet (Backend API)

Este arquivo define os padrões técnicos e arquiteturais para o desenvolvimento do servidor NestJS.

## 🎯 Visão Geral do Projeto

API robusta responsável pela persistência, segurança e lógica de negócio do ecossistema Master-Sheet. Focada em performance de busca (Tags) e integridade de dados dinâmicos (JSON).

## 🏗️ Tech Stack

- **Framework:** NestJS (TypeScript).
- **ORM:** Prisma com PostgreSQL.
- **Autenticação:** Passport.js + JWT Strategy.
- **Validação:** Class-validator + Class-transformer.
- **Documentação:** Swagger (@nestjs/swagger).

## 🛠️ Padrões de Desenvolvimento

1. **Arquitetura de Módulos:** Cada entidade principal (User, Template, Sheet, Tag) deve ter seu próprio módulo, controller e service.
2. **DTOs (Data Transfer Objects):** Obrigatórios para toda entrada de dados. Use `PickType` ou `PartialType` do NestJS para reaproveitamento.
3. **Services Puros:** A lógica de negócio pesada (como cálculos de RPG) deve ficar nos services, mantendo controllers magros.
4. **Tratamento de Erros:** Usar `Built-in HTTP Exceptions` do NestJS (ex: `NotFoundException`).
5. **Prisma Middleware/Logic:** - Implementar lógica de `connectOrCreate` para Tags.
   - Garantir que deletar um Template não delete as Fichas, somente não permita criar novas fichas a partir do Template deletado (usar Soft Delete ou Set Null, conforme regra de negócio).

## 📊 Regras de Negócio Backend

- **JSON Schema:** O Backend deve validar se a `Sheet.data` é compatível com a `Template.structure` (se possível, via um helper de validação JSON).
- **Isolamento de Tags:** Endpoints de `Sheet` só podem alterar `SheetTags`. Endpoints de `Template` só podem alterar `TemplateTags`.
- **Propriedade:** Toda mutação (Update/Delete) deve validar se o `req.user.id` é o dono do recurso.

## 🤖 Instruções para o Antigravity

- **Migrations:** Sempre que sugerir mudança no `schema.prisma`, gere o comando de migrate correspondente.
- **Testes:** Sugira testes unitários simples para lógica de cálculo de atributos.
- **Swagger:** Adicione decorators `@ApiTags` e `@ApiOperation` em novos controllers.
