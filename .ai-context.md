# 🧠 AI Context: Master-Sheet (Monorepo)

Este arquivo serve como a "Fonte da Verdade" para o desenvolvimento assistido por IA. Toda geração de código, refatoração ou criação de funcionalidades deve respeitar as definições abaixo.

## 🎯 Visão Geral do Projeto

O **Master-Sheet** é um ecossistema para gerenciamento de fichas de RPG com foco em **flexibilidade total**. O sistema permite a criação de templates dinâmicos (JSON-based) que definem a estrutura de qualquer sistema de RPG.

## 🏗️ Arquitetura e Tech Stack

- **Workspace:** Monorepo gerenciado por **Turborepo**.
- **Gerenciador de pacotes:** o projeto usa **pnpm**.
- **Backend:** NestJS (Node.js) com TypeScript.
- **Frontend Web:** Next.js (App Router) + Tailwind CSS + Lucide Icons.
- **Mobile:** React Native (Expo) + NativeWind.
- **Banco de Dados:** PostgreSQL via **Prisma ORM**.
- **Autenticação:** JWT (Passport.js) + Bcrypt.

## 📂 Estrutura do Workspace

- `apps/server`: API NestJS (Core do sistema).
- `apps/web`: Aplicação Next.js (Dashboard e Editor de Fichas).
- `apps/mobile`: Aplicativo Expo (Consulta e edição rápida).
- `packages/database`: Schema do Prisma e cliente compartilhado.
- `docs/`: Documentação de regras de negócio e diagramas.

## 🛠️ Padrões de Desenvolvimento (Guia de Estilo)

### 1. Backend (NestJS)

- **Modularização:** Seguir o padrão de módulos do NestJS (`src/auth`, `src/sheets`, etc).
- **Tipagem:** Uso obrigatório de DTOs (Data Transfer Objects) com `class-validator`.
- **Segurança:** - Usar Decorator `@GetCurrentUser()` para acessar dados do usuário logado.
  - Jamais expor o campo `password` em retornos de API.
- **Prisma:** Utilizar `connectOrCreate` para manipulação de Tags.
- **Identificadores:** Todos os IDs devem ser **UUID v4**.

### 2. Frontend (Next.js & React Native)

- **Componentização:** Preferir componentes funcionais e "Clean Components".
- **Estilização:** Utility-first com Tailwind (Web) e NativeWind (Mobile).
- **Gerenciamento de Estado:** Priorizar Server Components no Next.js e React Query para cache de dados.

## 📊 Regras de Negócio Críticas

1. **Templates vs Sheets:**
   - Um `Template` define a **estrutura** (layout/campos) via JSON.
   - Uma `Sheet` (Ficha) é uma **instância** de um Template, onde os valores reais são salvos no campo `data` (JSON).
2. **Privacidade:** Templates podem ser `IsPublic: true` (disponíveis para todos) ou privados.
3. **Lógica de Tags (Dualidade):**
   - **Escopo de Template:** Ao buscar templates, as tags servem para filtragem por sistema/gênero. Se um usuário "usa" um template público, ele não pode alterar essas tags.
   - **Escopo de Ficha:** O usuário tem liberdade total para adicionar/remover tags em suas `Sheets`. Essas tags são privadas e não afetam o `Template` original nem outras fichas de outros usuários.
   - **Persistência:** Continuar usando a lógica `connectOrCreate` no Prisma, mas garantindo que a relação (n:n) aponte para a entidade correta (`TemplateTag` ou `SheetTag`).

## 🤖 Instruções para o Agente (Antigravity)

- **Contexto de Arquivo:** Sempre verifique o `schema.prisma` em `packages/database` antes de sugerir mudanças em modelos ou repositórios.
- **Consistência:** Ao criar uma nova funcionalidade no Backend, sugira a implementação correspondente no Frontend Web.
- **Commits:** Siga o padrão de Conventional Commits (ex: `feat(api): add dynamic field validation`).
- **Terminal:** Você tem permissão para rodar `npm install`, `npx prisma generate` e `npx prisma migrate dev` após alterações de dependências ou banco.
